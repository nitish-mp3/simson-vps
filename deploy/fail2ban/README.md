# Anonymous SIP scan protection

Install `simson-anonymous.conf` in `/etc/fail2ban/filter.d/` and `simson-anonymous.local` in `/etc/fail2ban/jail.d/`. Validate with `fail2ban-client -t` and `fail2ban-regex` against representative rejected PJSIP messages before reload.

This filter recognizes UDP/TCP source prefixes and file-log authentication failures which the installed legacy filter misses. It matches anonymous calls rejected by the locked-down anonymous context and failed PJSIP authentication, not successful registrations or permitted gateway ingress. Six such failures in a minute ban the source for one hour across protocols. Repeatedly incorrect credentials can therefore block a legitimate device's public IP too; correct its credentials before unbanning. Do not remove authentication or weaken the anonymous dialplan to quiet scanners.

Add `simson_security => security` under `[logfiles]` in `/etc/asterisk/logger.conf`, then run `asterisk -rx "logger reload"`. This only reloads logging, not SIP transports or call state. Install `simson-security-logrotate` as `/etc/logrotate.d/simson-security`. The jail also reads this channel to match `FailedACL` for the anonymous endpoint's `registrar_attempt_without_configured_aors` event. Ordinary anonymous REGISTER warnings have no source IP and cannot safely identify an attacker; the security event provides the actual remote address. Successful authentication, challenges, and legitimate endpoint events do not match this additional rule. Keep the security log restricted to administrators; it contains endpoint names and network addresses.

`pjsip set logger on` prints full SIP signaling, including routine registration and OPTIONS traffic. Use `pjsip set logger off` for normal operation or `pjsip set logger host <gateway-public-IP>` for bounded diagnosis on this server's Asterisk version. Switching packet logging does not disconnect endpoints. Do not silence warning/security logs as a substitute for blocking rejected traffic. An empty contact list match alone does not prove a source is malicious: confirm rejected requests/security events before a manual ban.

`asterisk -rvvv` deliberately enables verbose channel output. Use `asterisk -r` for a quiet console; security rejection notices remain useful. Rejected INVITEs do not establish that an attacker authenticated or completed a call.

`asterisk.gateway_rtp_timeouts` is an opt-in map, for example `{"1701":120}`. Only that endpoint gets an inbound-media timeout; held calls get three times that interval. Continuous normal RTP, including silent audio packets, keeps the call alive. It mitigates missing BYE only when the gateway also stops RTP. If the analog gateway continues media after PSTN disconnect, its disconnect detection must be corrected on the device; this safeguard cannot infer a remote hangup from ongoing media.
